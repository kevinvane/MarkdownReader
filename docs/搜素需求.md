# "搜索" 功能需求

**文档版本**：v1.0
**适用范围**：MarkdownReader（当前单文件阅读器）
**依赖现状**：主进程 IPC（`open-file-dialog` / `file-opened` 等）、渲染进程 `contextIsolation` 隔离环境

---

## 1. 功能目标

允许用户在**当前打开的 Markdown 文件**内搜索内容，支持大小写敏感与正则表达式切换，结果按行展示并高亮匹配片段，点击结果可跳转到主内容区的对应位置。

**本期范围（明确）**：
- 仅搜索**当前打开的一个文件**，不涉及跨文件。
- 搜索对象为 **Markdown 源码文本**（包含 `#`、`*` 等语法符号），非渲染后的可见文本。
- 搜索在**渲染进程内存中**完成，**不新增任何 IPC 通道**，不依赖主进程文件遍历。

**本期不做（明确排除）**：
- ❌ 跨文件搜索、按文件分组展示结果。
- ❌ 打开文件夹 / 工作区 / 文件树等基础设施。
- ❌ 主进程流式遍历文件系统。
- ❌ 编辑、替换、保存。

---

## 2. 用户故事

- 作为用户，我希望按 `Ctrl+F` 快速唤起搜索面板，且输入框自动获得焦点。
- 作为用户，我希望输入关键词后能实时看到当前文件内的所有匹配行。
- 作为用户，我希望每条结果显示行号、该行内容，并在结果与主内容区同时高亮匹配片段。
- 作为用户，我希望能切换大小写敏感（`[Aa]`）和正则表达式（`[.*]`）模式，且切换后立即重搜。
- 作为用户，我希望点击某条结果后，主内容区能滚动到对应位置。
- 作为用户，我希望按 `Esc` 或再次按 `Ctrl+F` 可关闭面板并清空搜索状态。

---

## 3. UI 布局

底部可折叠面板，默认隐藏。面板内自上而下分三栏：

```
┌──────────────────────────────────────────────┐
│ [🔍 输入框……]  [Aa] [.*]   共 N 个匹配 / M 行  │  ← 搜索栏
├──────────────────────────────────────────────┤
│  12 │ 这是包含关键词的一行内容                 │  ← 结果列表
│  45 │ 另一行也包含关键词                      │     （行号 + 行内容，匹配片段 <mark> 高亮）
│  ...│ ...                                    │
├──────────────────────────────────────────────┤
│  第 x / y 个匹配                              │  ← 状态栏
└──────────────────────────────────────────────┘
```

- **搜索栏**：输入框 + 大小写切换按钮 `[Aa]` + 正则切换按钮 `[.*]` + 匹配计数。
- **结果列表**：按**行**平铺展示（单文件无分组），每行显示行号与内容，超长行省略号截断。
- **状态栏**：显示当前选中结果位置（第 x / y 个匹配）。
- **主题适配**：面板、高亮颜色随 `body.light-mode` / `body.dark-mode` 双主题变化。

## 4. 交互流程

```
1. 用户按 Ctrl+F（或再次按 Ctrl+F）
   → 搜索面板从底部滑出/收起
   → 展开时输入框自动获得焦点并全选已有文本

2. 用户输入关键词（每次输入触发 300ms 防抖）
   → 面板显示加载/搜索中状态
   → 渲染进程对 rawMarkdown 逐行匹配
   → 实时更新结果列表与匹配计数

3. 用户切换 [Aa] 或 [.*] 开关
   → 立即取消防抖，用新模式重新执行搜索

4. 用户点击某条结果（或输入框内按 Enter / Shift+Enter 在结果间跳转）
   → 主内容区滚动到对应行
   → 该匹配在内容区短暂高亮
   → 状态栏更新为"第 x / y 个匹配"

5. 用户按 Esc
   → 搜索面板关闭
   → 清空输入与搜索结果，移除内容区高亮
```

## 5. 功能详述

### 5.1 快捷键

- `Ctrl+F`（macOS 为 `Cmd+F`）：开/关搜索面板。
- `Esc`：关闭面板并清空状态。
- 快捷键在**渲染进程**内通过 `keydown` 监听实现，**无需修改菜单或主进程**（当前菜单无 find 项，且不加也无碍）。
- 输入框内 `Enter` / `Shift+Enter`：在结果之间正向/反向跳转。

### 5.2 匹配规则

- 默认：**不区分大小写**、**字面匹配**（非正则）。
- `[Aa]` 开关：开启后区分大小写。
- `[.*]` 开关：开启后按 JavaScript `RegExp` 匹配；同时支持大小写开关组合。
- 匹配粒度：按**行**匹配（逐行执行正则/`includes`），返回命中行号与首个匹配位置。

### 5.3 结果列表

- 每条结果：`行号 | 行内容`，匹配片段以 `<mark>` 高亮。
- 多匹配行的多次命中：单行内可展示全部命中（高亮全部片段），但计数按行计或按命中计需在实现中明确（本期建议按**行**计入列表、状态栏按**命中总数**统计）。
- 超大文件：结果列表最多渲染前 500 条，顶部提示"匹配较多，仅显示前 500 条"。

### 5.4 点击跳转定位

- 点击结果后，主内容区滚动到包含该匹配的位置并高亮该匹配。
- 实现约束：由于搜索针对源码行号，而行号到渲染后 DOM 的映射为**近似**实现（可借助 markdown-it 块级 `token.map` 建立"源码行 → 块元素"映射），验收标准是"匹配所在位置进入视口且可被识别"，**不要求逐像素精确对齐**。
- 新文件打开或内容变化后，旧高亮与搜索状态需清空。

### 5.5 主题

- 结果高亮、面板背景、输入框样式均需在浅色/深色两套主题下可读。
- 复用现有 `body.light-mode` / `body.dark-mode` class 机制，不新增主题切换入口。

## 6. 数据流与状态（无新增 IPC）

```
renderer.js
  ├─ renderMarkdown(content, filePath)
  │     └─ 新增状态：rawMarkdown = content   // 当前只存了 currentHtml
  │
  └─ 搜索面板逻辑（纯渲染进程内存操作）
        ├─ 读取 rawMarkdown，按 '\n' 拆分为行数组
        ├─ 按当前模式逐行匹配，生成结果列表
        └─ 点击结果 → 行号映射到 DOM → scrollIntoView + 临时高亮
```

- **新增状态变量**：`rawMarkdown`（当前打开的源码全文，仅内存持有）。
- **不新增 IPC**：搜索完全基于已加载内容，符合 `contextIsolation` 安全边界（渲染进程不接触 `fs`）。
- **高亮移除**：Esc 关闭、重新搜索、打开新文件时，清除主内容区残留高亮。

---

## 7. 错误处理与边界情况

| 场景 | 行为 |
| :--- | :--- |
| 未打开任何文件时按 `Ctrl+F` | 面板照常打开，结果区显示"请先打开一个 Markdown 文件"提示 |
| 输入框为空 | 结果区显示"输入关键词开始搜索"，不计匹配 |
| 无匹配结果 | 显示"未找到匹配项" |
| 正则表达式非法 | 输入框以红色边框提示错误，不崩溃、不执行搜索，显示错误信息 |
| 空文件 | 按无匹配处理，显示"未找到匹配项" |
| 超大文件 | 300ms 防抖避免卡顿；结果截断至前 500 条并提示 |
| 打开新文件 | 清空搜索面板状态与内容区高亮 |

## 8. 验收标准（AC）

1. **[正向]** 打开含表格、代码块、列表的 `.md` 文件，按 `Ctrl+F` 输入关键词，面板展开且输入框聚焦，结果按行展示、匹配高亮。
2. **[实时]** 输入过程中结果随防抖更新，切换 `[Aa]` / `[.*]` 后立即按新规则重搜。
3. **[正则]** 开启 `[.*]` 输入 `^#+ ` 能匹配所有标题行；输入非法正则不崩溃并提示错误。
4. **[跳转]** 点击任意结果，主内容区滚动到对应位置并高亮该匹配。
5. **[关闭]** 按 `Esc` 面板关闭、输入清空、内容区高亮移除；再次按 `Ctrl+F` 可重新打开。
6. **[主题]** 浅色与深色模式下，面板与高亮均清晰可读。
7. **[安全]** 搜索逻辑不新增 IPC、不引入 `fs` 访问；`contextIsolation` 边界不变。
